MindScreen: project summary

Multimodal student wellbeing screening: five data categories, one unified pipeline, honest limits.

Research gap

  • Most student screening relies on self-reported questionnaires: subjective, open to social-desirability and cultural bias, and a one-time snapshot.
  • Many ML prototypes use small or synthetic data, report accuracy only, and judge a student on a single average, hiding recent change.
  • Few prototypes go beyond a score to something an institution or hospital can act on responsibly (consent, access control, audit, aggregate reporting).

Problem statement

Estimate a student's wellbeing risk indicator from passively measurable and voluntarily shared data across five categories, track change against the student's own baseline, and deliver the result in a privacy-preserving, role-controlled workflow, without presenting it as a diagnosis.

Objectives

  1. Replace the single questionnaire with five separately uploaded data categories, validated and stored in one unified structure.
  2. Train and compare 4 models (Logistic Regression, Random Forest, Gradient Boosting, SVM) on a real public student dataset ({{ s.n_rows }} records) and report honest hold-out metrics.
  3. Run one unified prediction pipeline that states which categories it used, how sufficient the data is, and what it could not use.
  4. Explain each result with SHAP, and show trends with missing days left as gaps.
  5. Provide consent, deletion, role-based access, an audit log and k-anonymised researcher aggregates.

Methodology

  1. Training data: public survey dataset; target = wellbeing score ≤ {{ s.threshold }}/10. Questionnaire-derived and self-reported columns are excluded.
  2. Model inputs: average social-media hours, average sleep hours, top platform, age, gender, academic level + 3 engineered ratios.
  3. Models: LR, RF, GB, calibrated SVM; GridSearchCV (5-fold, F1) on an 80% training split; 20% held-out evaluation; subgroup check.
  4. Platform pipeline: validated uploads → unified per-student features → prediction + SHAP → stored with model version and timestamp.
  5. Change monitor: last 7 days vs own baseline (≥ 2.5 standard errors and ≥ 10% worse), unvalidated heuristic.

What is real and what is a placeholder

  • Real: accounts, roles, consent, uploads, validation, storage, trends, reports, audit log, aggregate reporting, the trained model and SHAP.
  • Limit: the model can only use screen-time and sleep (plus profile). Behavioural, social and academic data are collected and shown but not scored, because the training data has no such columns.
  • Demo: demo accounts hold fictional records and are kept separate from real data.

Future scope

  • Hospital / counselling tie-ups with consent-based referral; clinic-labelled outcomes to train and validate a true multi-category model.
  • Companion app / connectors (Digital Wellbeing, Screen Time, Health apps) replacing manual upload; wearable and EEG features.
  • Sequence models on daily series; bias audit and clinical validation before any deployment.
